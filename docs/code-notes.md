## 一、ExtJS 的展开图标是「切换」而不是「展开」

这是整个采集环节里最关键的一个坑。

**现象**

点击树形菜单父节点旁的展开图标后，子节点有时反而**消失**了，随后所有针对子节点的点击全部超时。

**原因**

ExtJS 的 `expander` 图标是**切换（toggle）**语义，不是「展开（set expanded）」语义。
如果父节点本来就处于展开状态，再点一下就会把它**收起**。

**常见但错误的判据**

以「点击动作是否抛异常」判断成功：

```text
点一下 expander
若没报错 → 认为已展开，继续
```

这种写法在「父节点本已展开」时会把树点收起来，**而且自己不知道**。

**实际采用的判据**

不检查动作，检查**后置条件**——子节点是否真的可见：

```text
ensure_child_visible(父节点, 子节点, 最大尝试次数):
    重复 最大尝试次数 次:
        若 子节点 已可见:
            返回 成功                      // 已是目标状态，什么都不用做
        若 父节点行 存在:
            点击 该行内的 expander
            等待 界面稳定
        否则:
            等待 一小段时间                  // 页面还没渲染好，下一轮再试
    返回 失败                              // 有界重试耗尽，交给调用方处理
```

**四个设计要点**

| 要点 | 为什么 |
|---|---|
| **先检查后动作** | 已经是想要的状态就不动它——从根上避免误收起 |
| **失败后重新点** | 点第二次等于把状态「拨回来」，而不是记录一个失败的布尔值 |
| **有界重试** | 不无限循环；耗尽后返回失败，由上层决定怎么办 |
| **返回布尔而非抛异常** | 调用方能给出业务化提示（「展开菜单失败」），而不是把调用栈抛给用户看 |

**通用教训**

自动化一个**有状态的界面**时，「动作是否执行成功」与「界面是否达到期望状态」是两件事。
判据要取后者。

这条不限于 ExtJS——任何可切换的控件（折叠面板、开关、多选）都适用。

## 二、同名按钮只点可见的那个

**现象**

ERP 工具栏上「查询」这类按钮**同时存在于多处**：单据编辑页有一个，列表页也有一个。
按文本选择器抓会抓到多个，点到隐藏的那个就什么也不会发生，而且不报错。

**处理逻辑**

```text
click_button(按钮文本):
    对每个 候选选择器（由具体到宽泛）:
        定位所有匹配元素
        若 一个都没找到:
            换下一个选择器
        否则:
            遍历 前 N 个匹配元素:
                若 该元素当前可见:
                    点击它
                    记录日志并返回 成功
    记录「所有候选均不可见或未找到」
    返回 失败
```

**四个设计要点**

| 要点 | 为什么 |
|---|---|
| **多套选择器依次降级** | 同一框架的不同版本/主题 DOM 结构会变，写死一套容易在升级后失效 |
| **只点可见的** | 「找得到」不等于「能点」——隐藏元素点击无效且通常不报错 |
| **遍历有上限**（如 8 个） | 防止某个选择器意外匹配到上百个元素时空转 |
| **失败要留痕** | 记录「点了但没成」，调用方才能区分「没找到」和「找到了但点不动」 |

## 三、为什么这两个点值得单列

它们代表这类工作的**真实难点**。难点不在「会调浏览器自动化 API」，而在：

1. **理解被操作界面的状态语义** —— 是 toggle 还是 set？这决定了判据怎么写
2. **为不确定性设计判据** —— 后置条件优于动作返回值
3. **在会变的外部依赖上做兼容** —— 多套选择器、逐级降级、失败留痕

这三条都不是从文档里读来的，是被真实的失败逼出来的。

## 四、为什么本文不放原始代码

工具对接的是**具体客户的 ERP 系统**。虽然已确认实现中不含客户标识、
账号或业务数据，但**公开发布源码节选的授权尚未从相关方获得确认**。

在授权明确之前，本仓库采取保守做法：

- 不发布任何原始代码（哪怕是片段）
- 用重新编写的伪代码表达算法逻辑
- 技术结论照常给出，并可独立复核

如果后续确认了授权，可以再补入原始节选；在那之前，本文的伪代码已足够说明设计意图。
