# 流程

本文对比**人工流程**与**自动化流程**，并标清每一步由谁完成。
分界线很重要：能自动化的自动化，该由人决定的绝不自动化。

---

## 一、月度对账的完整流程

### 原来：全人工

```
① 打开 ERP 网页，登录
        │
② 菜单：产品 → 供应商平台 → 供应商送货单
        │
③ 按月份查询，得到列表
        │
④ 逐页手抄：日期 / 单号 / 行号 / 料号 / 规格 / 数量
        │   ← 最容易出错的环节
        │
⑤ 打开 Excel 母版，按料号逐行填入
        │
⑥ 对每个料号，翻产品资料查单价，填到单价列
        │   ← 漏查 = 金额错
        │
⑦ 按当月有业务的日期，手工插入日期列，把数量填进对应格子
        │   ← 日期列与数据错位是常见错误
        │
⑧ 核对合计
        │
⑨ 交给客户
```

痛点集中在 ④⑥⑦：**都是机械重复、容易错、且错了要到 ⑧ 才发现。**

### 现在：只读采集 + 确定性生成

```
① 双击启动 → 程序自检（驱动 / Edge / 配置 / 资料目录）
        │
② 弹窗选账号（两个账号各对应一套 ERP 与母版）
        │
③ 程序打开 Edge（持久化 Profile）
        │
   ┌────┴─────────────────────────────────────┐
   │ 登录状态还在？                             │
   │   是 → 自动进主界面                        │
   │   否 → 弹窗提示人工登录，登录后备份状态       │
   └────┬─────────────────────────────────────┘
        │
④ 程序自动：进菜单 → 查询 → 翻页读取全部记录
        │   （读到早于目标月份的记录即停；有最大页数上限兜底）
        │
⑤ 程序输出：当前月份记录.csv + 采集报告
        │   （含重复行数、页数、记录数、日期区间）
        │
⑥ 程序生成：复制母版 → 匹配料号取单价 → 按日期+料号汇总
        │          → 动态日期列 → 写公式 → 跑质检
        │
⑦ 程序输出：对账单 .xlsx（成品目录）+ statement_report.json
        │   （含缺单价料号清单、质检结论）
        │
⑧ 人工审核：看报告 → 补单价 → 复核异常 → 确认
        │
⑨ 交给客户
```

## 二、每一步由谁完成

| 步骤 | 人 | 程序 | 说明 |

| 环境自检 | | ✅ | 驱动、Edge、配置、资料目录 |

| 翻页读取 | | ✅ | 含终止条件与安全上限 |
| 去重 | | ✅ | 唯一键见 [business-rules.md](business-rules.md) |
| 写中间产物 + 报告 | | ✅ | CSV / JSON |
| 匹配料号与单价 | | ✅ | 规格交叉验证，名称仅提示 |
| 汇总与日期列 | | ✅ | 按「单据日期 + 料号」汇总 |
| 写母版与公式 | | ✅ | 保留母版样式 |
| 质检 | | ✅ | 区分 fatal / 非 fatal |
| **补单价** | ✅ | | 程序名单，人填数字 |
| **判断同物异名** | ✅ | | 程序只提示，不阻断 |

**一句话**：程序负责「搬数和算数」，人负责「判断和负责」。

## 三、程序在哪些地方主动停下来

这几处是有意设计的停顿，不是没做完：

**1. 登录环节**

```
登录掉了 → 弹窗提示 → 人工在浏览器里登录 → 点确定 → 程序继续
```

程序既不保存也不输入账号密码。登录状态存在本地 Profile 里，属于「浏览器记住了」，不属于「程序记住了」。

**2. 料号在产品资料里找不到**

按模块文档的规则，这是**明确异常**，不是警告：

```
料号不存在于产品基础资料 -> 明确异常, 不允许猜, FINAL=FAIL
```

宁可使整份对账单失败，也不用相似度猜一个料号——猜错的代价是给客户的账目出错。

**3. 名称对不上但规格对得上**

这是**提示**而非阻断：`match_products` 以料号为主键、规格做交叉验证、名称只作辅助。
因为现实中确实存在同一物料不同叫法的情况，但最终判断必须由人做。

**4. 缺单价**

程序按规则把金额填 0（金额公式保留），同时把缺单价的料号列进清单。
人补完单价后**重跑一次**，金额就出来了。这样「缺数据」不会变成「错数据」。

## 四、翻页的终止条件

翻页循环有两个独立的停止条件，缺一不可：

| 条件 | 作用 |
|---|---|
| 读到早于目标月份的记录 | 正常终止：ERP 列表按日期倒序，读到上个月说明当月已读完 |
| 达到最大页数安全上限 | 异常兜底：防止因判断逻辑失效而无限翻页 |

两条都记录在采集报告里，报告会写明本次是**因为哪个条件停的**、读了多少页、多少条记录、日期区间是什么。

这是「让结果可被质疑」的做法：如果程序提前停了，报告里看得出来。

## 五、失败时发生什么

| 环节 | 失败表现 |
|---|---|
| 自检 | 启动前就报出具体原因（驱动异常 / 找不到 Edge / 配置或资料目录不可读） |
| 采集 | 提示"数据采集未成功，请查看日志后重试"；日志窗口保留异常信息 |
| 生成 | 提示"对账单生成未成功，请查看日志窗口" |
| 质检 | fatal 项不过 → 整体不通过，报告里列出是哪一项 |
| 浏览器 | 记录到 `error` 字段并在报告里体现 |

设计取向：**宁可失败得吵，也不要失败得静。**

## 六、两个账号怎么共存

配置里有多个账号，每个账号对应一套：

- 一个 ERP 网址
- 一份母版（版式可能不同）
- 一组模板坐标（行列位置、列号、各类偏移量）
- 一个单价模式
- 独立的 `output\<id>\` 与 `profiles\<id>\` 目录

**产品资料是两个账号共用的**——同一套料号和单价，避免同物两价。

运行时会记录「本次用的是哪个账号」，成品文件名也带月份，便于归档。
