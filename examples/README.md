# 示例数据说明

## ⚠️ 全部虚构

`sample-reconciliation-data.xlsx` 里的**每一个名称、料号、规格、单价、数量都是编造的**，
与任何真实公司、客户或业务无关。

它只用来演示：

- 数据长什么样（列结构）
- 工具需要处理哪些字段
- 业务规则会遇到哪些边界情况

**不得**据此推断任何真实业务的规模、价格或对账结果。

---

## 怎么来的

```bash
python examples/make_sample_data.py
```

随机种子固定（`SEED = 20260801`），所以每次生成的结果完全一致，便于核对。

需要 `openpyxl`：

```bash
pip install openpyxl
```

## 三个工作表

### 1. 产品基础资料

| 列 | 含义 |
|---|---|
| 料号 | 匹配主键。**业务上是字符串，不是数字**（见 R9：浮点料号问题） |
| 规格型号 | 用于交叉验证（料号为主键，规格做二次确认） |
| 名称 | 仅作辅助提示，**不阻断匹配** |
| 单位 | 件 / 个 |
| 单价（未税） | 金额计算的来源 |
| 备注 | 标注刻意植入的情况 |

共 6 个虚构料号，其中 **`DEMO-1005` 刻意不给单价**。

### 2. 送货单明细

| 列 | 含义 |
|---|---|
| 单据编号 | 与行号共同构成唯一键 |
| 行号 | 同一张单内的序号 |
| 单据日期 | 汇总键的一部分（不是创建时间） |
| 料号 | 关联产品资料 |
| 数量 | 正数送货；负数表示退货（真实场景中退货数量前加负号） |

共 43 行，含刻意植入的边界情况。

### 3. 说明

把上面这些边界情况逐条写在工作表里，打开文件就能看到，不必翻文档。

## 刻意植入的四种边界情况

这四种情况是**从真实对账场景里总结出来的易错点**，示例数据把它们都造了出来：

| 标记 | 情况 | 对应规则 | 期望行为 |
|---|---|---|---|
| **A** | 同一「单据编号 + 行号」出现两次 | R1 | 去重后只保留一条 |
| **B** | 同一天对同一料号的两笔 | R2 | 数量**求和**，不是重复 |
| **C** | 同一天 + 同料号 + **同数量**的两笔 | R2 | **必须保留两条**——这是最容易被误删的情况 |
| **D** | `DEMO-1005` 没有单价 | R6 | 金额填 0，并进「缺单价清单」 |

### 为什么 C 最关键

如果有人用「日期 + 料号 + 数量」当去重键，C 这种情况会被**错误地合并成一条**——
账面上就少了 400 件。这正是规则里明确禁止那种去重方式的原因。

同一张单的同一行重复抓取（情况 A）才是真正的重复，而它靠 A 的键就能准确识别。

**示例数据存在的意义，就是让这个区别可以被验证，而不是靠嘴说。**

## 数据规模

| 项 | 数量 |
|---|---|
| 虚构料号 | 6 |
| 虚构送货单明细行 | 43 |
| 其中同单同行重复 | 1 |
| 涉及的业务日期 | 9 天（2026-08 内） |
| 缺单价的料号 | 1 |

规模刻意做小，方便人工核对每一条规则。

## 与真实工具的差距

这份示例**只保留了对账逻辑需要的字段**。真实采集输出还会包含：

- 采集时间、页数、总记录数
- 翻页终止原因
- 去重行数
- 每个页面的行数与表头定位方式

这些属于**采集报告**，不在本示例范围内。
采集报告的字段构成见 [../docs/architecture.md](../docs/architecture.md)。
